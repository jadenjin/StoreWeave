# S3 Provider

`storeweave-provider-s3` 使用 AWS SDK for Java 2.x，适用于 AWS S3 以及支持 S3 API 的兼容服务。AWS 类型只存在于该 Provider 内，不会进入 Core 公共 API。

RustFS 使用同一模块内的独立 `rustfs` 类型，以获得 endpoint、凭证和 path-style 的专用校验与默认值，配置见 [RustFS Provider](rustfs.md)。

## 引入与配置

应用在 Starter 之外显式引入 `storeweave-provider-s3`。项目当前只从源码构建，不配置远程 Maven 发布。

```yaml
storeweave:
  primary: s3
  stores:
    s3:
      type: s3
      endpoint: http://127.0.0.1:9000
      region: us-east-1
      access-key: ${AWS_ACCESS_KEY_ID}
      secret-key: ${AWS_SECRET_ACCESS_KEY}
      session-token: ${AWS_SESSION_TOKEN:}
      options:
        path-style-access: true
```

| 配置 | 必填 | 默认值 | 说明 |
|---|---:|---|---|
| `type` | 是 | — | 固定为 `s3` |
| `endpoint` | 否 | AWS SDK 默认地址 | S3 兼容服务使用绝对 HTTP(S) 地址 |
| `region` | 否 | `us-east-1` | AWS Region；兼容服务也需要一个签名 Region |
| `access-key` / `secret-key` | 否 | AWS SDK 默认凭证链 | 必须同时提供或同时省略 |
| `session-token` | 否 | — | 临时静态凭证使用 |
| `options.path-style-access` | 否 | `false` | 兼容服务常需设为 `true` |

省略静态凭证时使用 AWS SDK 默认凭证链，包括环境变量、JVM 系统属性、Web Identity、共享凭证文件、容器和实例角色。不要把密钥写入源码或提交到 Git。

## 能力

| 能力 | 支持 | 说明 |
|---|---:|---|
| 通用对象操作 | ✓ | 上传、下载、元数据、存在性、删除、token 分页 |
| `BucketOperations` | ✓ | 创建、检查、列表和删除桶 |
| `PresignOperations` | ✓ | 预签 GET 与 PUT |
| `MultipartOperations` | ✓ | 发起、上传 Part、列出 Part、完成和终止 |
| 生命周期、通知、配额、服务管理 | — | 不声明未实现能力 |

## 错误和重试语义

SDK 异常统一映射为 `StorageException`。HTTP 408、429 和 5xx，以及 SDK 客户端传输错误会标记为可重试；认证失败、对象不存在、冲突和请求无效默认不可重试。框架只提供可重试标志，当前不会在 Provider 内隐式重放写操作。

## 从旧实现迁移

1. 业务代码改为只依赖 `StorageClient` 和所需能力接口，不再暴露 `S3Client`、SDK Request 或 Response。
2. 把 endpoint、region、凭证和 path-style 迁到 `storeweave.stores.<name>` 配置。
3. 分页游标当作不透明 continuation token 使用，不解析或持久化其格式。
4. 预签与分片操作先通过 `client.capability(...)` 获取，避免假设所有 Provider 都支持。
5. MinIO Admin、配额和通知不要迁入 S3 Provider；它们属于后续独立 MinIO Provider。

模块测试通过真实 AWS SDK 请求一个进程内 S3 兼容 HTTP 服务，覆盖基础对象契约、分页、预签名、分片上传和错误映射，无需 Docker 或外部账号。
